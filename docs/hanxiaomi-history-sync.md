# 同步到汉小密中台

左侧选择「中台同步」，或在聊天页点击「同步当前聊天到中台」。

## 首次使用

1. 中台后端必须已发布历史同步接口并应用 `20261116_0093` 迁移。
2. 在中台微信账号列表点击对应微信的「本地历史同步」，复制 10 分钟有效的绑定码。
3. 在 WeFlow 填写中台 HTTPS 地址与绑定码。页面会显示机构、微信名称和真实 wxid，不能跨微信绑定。
4. 选择会话和时间范围，点击「开始同步」。附件与持续补齐默认开启。

首次同步建议选一段已知的私聊和群聊，保存对账报告后确认消息方向、时间、引用和附件。代码不写死账号：应在中台选择业务指定的账号签发绑定码。

## 运行和恢复

- 同步独立于「小密回复」，无需开启自动回复或 HTTP API 推送。
- 本地数据库密钥留在 WeFlow；中台同步凭据通过 Electron safeStorage 加密，不返回渲染页面。
- 状态、待传批次和附件队列位于应用 userData/history-sync。断网保留未确认批次，应用重启后按原状态恢复；手动暂停会保留。
- 每 30 秒补齐双向新增记录，每天重新读取历史并对账，发现后来迁移到本地的旧消息。
- 切换微信会暂停，不能把新账号记录写入旧账号。每个微信在中台仅允许一个活动同步任务。
- 同步到中台不会增加未读，也不会触发 AI 回复或营销。原生微信消息仍由原有中台通道处理。
- 冲突会话、无可靠编号的重复候选、附件缺失等显示在结果区；处理原因后点击「重试失败项」。缺失附件对应的消息仍保留。
- 「保存对账报告」输出会话/UTC 日期汇总、来源摘要及问题清单。

源码运行：`npm run dev`。构建：`npm run build`。专项验证：`npm run test:history-sync`、`npm run test:hanxiaomi`、`npm run typecheck`。

协议类型：`shared/wechatHistory.d.ts`。主进程实现：`electron/services/history-sync/`。
使用原始本地消息定位，不使用通用 JSON 导出文件中重新编号的 localId。
