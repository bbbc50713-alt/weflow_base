# 独立只读微信数据库读取器

Windows x64 的 `wcdbWorker` 使用本项目的 TypeScript 查询适配器与 SQLite3 Multiple Ciphers。
不会加载旧 `wcdb_api.dll`，也不会调用 WeLive；旧组件的校验逻辑和二进制文件保持原样。

## 依赖

- SQLite3 Multiple Ciphers 2.7.1 / SQLite 3.54.1，MIT 许可及第三方许可见 `resources/independent-reader/`。
- 来源与固定 SHA-256 见 `PROVENANCE.json`。`node scripts/prepare-independent-reader.cjs` 可校验或重新下载固定版本。
- Windows x64 之外的平台尚未接入新适配器，继续使用原有路径。

## 只读边界

数据库和 WAL 首先复制到应用 userData 下的加密快照目录。复制前后核对原文件大小和修改时间，不一致则拒绝本次读取。
SQLite 只打开副本，启用 READONLY 和 query_only。公开查询入口拒绝写语句、ATTACH 和多语句。
密钥仅用于内存中的连接，不写日志或快照元数据。原始微信数据库、WAL、SHM 不交给 SQLite 打开。
每页 HMAC 检查保持启用；不会通过关闭校验来伪造“连接成功”。

## 首版能力与边界

- 会话、联系人、头像 URL、备注、私聊与群聊消息、分库游标、长编号、收发方向、日期及类型统计。
- 通过已有 JavaScript 格式器导出 JSON / ChatLab / TXT / HTML / Excel / CSV；不再依赖 WeLive。
- 现有中台同步入口复用上述消息游标与身份字段。
- 群成员完整名册、复杂统计、朋友圈、消息修改/删除/恢复等未实现的方法返回明确错误。
- 当前尚未完成全部媒体资源索引适配；不能将“文本可读”当成“所有媒体已恢复”。
- 密钥不同的分库、不支持的表结构会报错，不静默写入错误身份或返回空成功。

## 验证

`node scripts/test-independent-reader.cjs` 验证加密 WAL 副本、错误密钥、原文件哈希不变、禁止写入、会话/联系人映射、同秒跨库分页与群发送者。
这些测试是临时数据测试；真实微信数据库的密钥、加密参数、表结构仍须实际连接验证。
连接失败时界面会保留“独立读取器：…”的错误原因，不再统一吞成旧组件错误码。
